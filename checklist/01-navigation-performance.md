# 01 — Навігація та швидкодія

Поточний стан: маршрути та короткі анімації є; тести анімації не вимірюють повну роботу контролера. Відомий software-renderer corner fixture може падати до переходу. Деталі: [аудит](../docs/AUDIT-2026-11-04.md), [performance](../docs/PERFORMANCE.md).

## Відтворити затримку

- [ ] Зафіксувати точні кроки, очікування/факт, сторінки та час появи зависання на кожному пристрої користувача.
- [ ] Записати модель пристрою, OS, Vey build, renderer, DPI/viewport, живлення й чи грає аудіо.
- [ ] Підготувати відтворювані набори 300, 2 000 і 10 000 треків із контрольованою кількістю артистів/альбомів/плейлистів.
- [ ] Підготувати історію 0/2 000/10 000 подій і перевірити сортування за Recently Played.
- [ ] Виміряти п'ять прогрітих повторів: cold open, повторний перехід, швидкі три retarget-и, повернення назад, Library categories, Settings, Liked, Queue, Explore, Player.
- [ ] Заміряти окремо input→callback, час синхронної роботи callback, input→перший кадр, settled time, p50/p95/max UI-loop gap.
- [ ] Повторити з обкладинками cached/uncached, повільною мережею, помилкою API, без мережі, активним local track та YTM stream.
- [ ] Повторити Windows GPU і software, браузерний WASM, реальний Android/AVD; зафіксувати відсутню платформу як неперевірену.

## Профілювання й оптимізація

- [ ] Додати opt-in профіль переходу без назв треків, повних шляхів, токенів або signed URLs.
- [ ] Виміряти `on_navigate` → `refresh`, побудову колекцій, формування playlist covers та передачу моделей у Slint.
- [ ] Перевірити, чи колекції перераховуються під час навігації на нерелевантну сторінку; рахувати реально оновлені моделі/рядки.
- [ ] Перевірити artwork queue, image decode, cache lookup, bridge message та Slint upload як окремі ділянки.
- [ ] Якщо hotspot підтверджено, додати revision-keyed collection cache й чітке invalidation після scan/tag/like/download/playlist edit.
- [ ] Якщо history sort підтверджено, будувати identity→lastPlayed map один раз на зміну історії, а не сканувати історію для кожного comparator виклику.
- [ ] Уникнути пошуку playlist cover у повному каталозі для кожного playlist повторно; виміряти результат на великих наборах.
- [ ] Розглядати lazy page models/virtualization лише з тестами відновлення актуальних likes, download status, art та selection.
- [ ] Зберегти generation/request ID і cancellation, щоб старий результат не перезаписував новішу навігацію.

## Візуальний рух

- [ ] Перевірити відсутність подвійного руху, стрибків, blank frame і некоректного кінцевого маршруту.
- [ ] Перевірити reduced motion і швидке перемикання маршруту під час анімації.
- [ ] Визначити renderer-specific допуск для субпіксельних кутів; тримати поведінкову clipping перевірку окремо від точної RGBA рівності.
- [ ] Порівняти blur/ambient/effects A/B перед будь-яким спрощенням анімації.

## Критерії завершення

- [ ] На еталонному desktop UI callback p95 ≤16 ms; callback понад 100 ms не з'являється на узгоджених синтетичних сценаріях.
- [ ] Desktop input→first movement p95 <50 ms; маршрут завершується в задекларований інтервал 160–180 ms плюс до двох кадрів.
- [ ] 10k треків не викликають непропорційного зростання часу порівняно з 2k; Android межі задокументовані за класом пристрою.
- [ ] Після змін scan, filter, sort, like, download, relink і швидкого retarget всі моделі лишаються коректними.
- [ ] До/після звіти з однаковою машиною, renderer, даними, кількістю повторів і сирими результатами збережені.
