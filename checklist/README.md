# Vey — повні чеклісти розвитку

Ця папка розбиває великий план Vey на робочі списки за підсистемами. Використовуй її як основний індекс для оцінювання прогресу; вихідний широкий огляд і виміри лишаються в [аудиті](../docs/AUDIT-2026-11-04.md).

## Як читати статус

- **Є в коді** — функція або базова реалізація знайдена у поточному дереві. Це не означає свіжу перевірку на кожній платформі.
- **Частково** — основний шлях існує, але відсутні важливі сценарії, крайові випадки чи platform acceptance.
- **Немає / не перевірено** — функція відсутня або немає достатніх свіжих доказів роботи.
- Порожній checkbox `[ ]` означає невиконану роботу. Позначати його `[x]` лише після перевірки критерію в цьому пункті й запису фактичного доказу.

## Порядок великих робіт

1. Відтворити зависання та виміряти повний шлях на кожній доступній платформі.
2. Виправити виміряні причини, пройти перевірки бібліотеки, обкладинок і активного відтворення.
3. Завершити каталог: typed search results, сторінки артистів/альбомів/плейлистів і pagination.
4. Закрити playback, локальну медіатеку, Android/Web gaps і recovery сценарії.
5. Завершити публічний Spotify playlist import → YTM без Spotify account; відмовляти неповні/неоднозначні imports.
6. Додати персональні функції, довести доступність і видаляти старе лише після заміни та міграції.

## Правила оновлення

- У чеклістах не приписувати браузерним тестам Android чи Windows native acceptance.
- Для live service check зазначати сервіс, тип даних (public/account), дату, версію парсера й кількість отриманих рядків; ніколи не записувати cookies, токени, підписані URL або повні особисті бібліотеки.
- Для продуктивності записувати однакове середовище й baseline до/після, а не лише «відчувається швидше».
- Зберігати незакомічені зміни й дані. Деструктивну міграцію або видалення не вважати виконаним без backup/rollback перевірки.
